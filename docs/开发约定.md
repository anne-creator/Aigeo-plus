## 必须遵守

- 只在自己负责的子目录里新建/修改文件（`src/app/pm/**`、`src/app/admin/**`、`src/app/intern/**`）。需要的 helper 放自己目录里，不要改共享文件。
- 不要 `npm install` 任何包；不要运行 `next build` / `next dev`（会互相冲突）。可以运行 `npx tsc --noEmit`（只修自己目录的报错）和 `npx eslint src/app/<你的目录>`。
- Next.js 16：`params` / `searchParams` 是 Promise，必须 `await`。页面签名写成 `{ params }: { params: Promise<{ id: string }> }`，不要依赖 `PageProps` 全局类型（它要 typegen 之后才有）。
- 所有页面都是 Server Component + Server Actions（`"use server"` 文件放在自己目录下的 `actions.ts`）。需要交互的小块才用 `"use client"`。
- 表单提交后用 `revalidatePath` + `redirect`。错误通过 `?error=` 查询参数回显（页面 `await searchParams` 读取后用 `<Alert tone="red">` 展示）。
- 用 `src/components/ui.tsx` 的组件保持风格一致；中文界面；时间一律用 `formatBj`。
- 项目权限：PM 只能看/操作 `project.pmId === session.uid` 的项目，查询时带 `where: { pmId: session.uid }`，详情页用 `canAccessProject` 校验，不通过就 `notFound()`。
- 金额用 `money()`，百分比用 `pct()`。
- 数据写入前用 `zod` 校验（已安装 zod v4：`z.object({...}).safeParse(...)`）。

## 第三轮需求（2026-10-20）：所有节点开放、可视化时间线、负责人任务

- **没有“未开放”状态了。** `DeliverableStatus` 只有 `OPEN / ON_TIME / LATE / OVERDUE`；所有节点 `windowStart = D0`，任何时候都能提交、跳步提交，只按截止日算延期。界面上不要再出现“未开放 / 窗口开始 / 即将开放”。
- **不做任何客户审核流程。** 需要客户认可的材料（如知识库），项目经理直接上传客户已通过的版本。管理员的内部“审核通过/不通过”保留（那是内部考核）。
- **“实习生”改称“负责人”。** 账号角色代码仍是 `INTERN`，但任何界面都不出现“实习生”字样。负责人类型见 `src/lib/tasks.ts` 的 `DUTY_ROLES`：视频分发负责人 / 用户共识层分发负责人 / 媒体分发负责人 / 专业润色写手（`User.dutyRole`）。
- **新数据模型：** `TaskBatch`（一次分配：projectId、assigneeId、dutyRole、sourceText 或 sourceFile*、itemsJson 草稿清单、parseMethod ai|rules、status DRAFT|CONFIRMED|DISCARDED）、`InternTask` 新增 `projectId / batchId / completedAt`、`TaskSubmission`（负责人交付：url 或 file*、note）。
- **`src/lib/tasks.ts`：** `DUTY_ROLES`、`dutyRoleLabel(v)`、`listAssignees()`、`organizeTasks(text, {today, roleLabel})` → `{items: DraftTask[], method}`（有 Anthropic 凭证时用 AI 整理，否则规则解析）、`extractTextFromFile(file)`（.txt/.md/.csv/.docx/.pdf）、`TASK_DOC_EXTENSIONS`、`parseItemsJson(json)`、`confirmBatch(batchId, items, userId)`（每条必须有标题+日期，写入 InternTask 并把批次标为 CONFIRMED）、`assigneeHasProject(userId, projectId)`。`DraftTask = { title, dueDate: YYYY-MM-DD | null, note }`。
- **文件下载：** 知识库仍走 `/api/files/<submissionId>`（负责人在该客户有任务时允许下载 KNOWLEDGE_BASE 的文件）；任务原始文档 `/api/task-files/source/<batchId>`；负责人交付文件 `/api/task-files/delivery/<taskSubmissionId>`。上传保存用 `saveUpload(file, subdir)`（`src/lib/files.ts`）。
- **导航：** PM 新增 `/pm/tasks`（分配任务）；负责人端 `/intern`（我的任务）和 `/intern/knowledge`（客户知识库）；`/intern/logs` 已从导航移除。
